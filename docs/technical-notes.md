# Технические заметки: Image Studio

Подробности исходной Windows-установки и предыдущих проверок. Пути и измерения ниже относятся к той установке; основные инструкции находятся в [README](../README.md).

# Qwen Image Studio

Локальная генерация PNG через **Qwen-Image 2.1 Uncensored Q4_K_M** и написание промптов через **Gemma 4 E4B Deep Abliterated / Uncensored Q4_K_M** из соседнего Qwen_Simple_Chat. Новый проект не меняет файлы соседних приложений.

## Запуск

1. `Install.cmd` скачивает веса и CUDA runtime, проверяет SHA256. При обрыве повторный запуск продолжает скачивание. Установка не запускает модели.
2. `Start Studio.cmd` открывает http://127.0.0.1:8795. При открытии интерфейса модели не загружаются.
3. Введи идею. «Написать промпт» запускает только Llama; «Создать изображение» использует введённый текст напрямую; «Улучшить и создать» последовательно выполняет оба этапа.

В интерфейсе два независимых списка: **генератор промптов** и **генератор изображений**. Выбор сохраняется в этом браузере. Списки обновляются каждые 5 секунд и кнопкой «Обновить список моделей»; файлы `.part`, незавершённые загрузки aria2, пустые файлы и вспомогательные энкодеры не предлагаются как модели генераторов.

Текстовые GGUF автоматически обнаруживаются в `D:\Quest3S_Workspace\Qwen_Simple_Chat\models`, включая модели без пометки Uncensored. Доступны модели до 13B; модели 20B, 26B и 27B видны, но отключены с объяснением ограничения текущего GPU-режима. Выбранная по умолчанию Gemma уже находится там и не скачивается повторно. Gemma E4B имеет примерно 8B общих параметров и 4.5B эффективных параметров вычисления, согласно карточке автора.

Для изображений обнаруживаются скачанные GGUF Qwen-Image 2.1 в `models` и каталоге моделей чата. Они используют настроенные `textEncoder` и `vae`; без этих компонентов генерация недоступна. Сейчас скачан один checkpoint — `qwen-image-2.1-UC-Q4_K_M.gguf`. Дополнительные каталоги можно задать массивами `promptModelRoots` и `imageModelRoots` в `config.json`. Пути и порты также задаются в этом файле; после изменения конфигурации перезапусти Studio. Выбранные модели передаются движкам и записываются в JSON результата.

FLUX подключена отдельным профилем: `aschjj/FLUX-UNCENSORED-merged`, revision `526da5e40b775db572090d769710e267b1d9634c`. `node download-flux.cjs` скачивает исходный snapshot (~33.9 ГБ) с проверкой SHA256 и продолжением через aria2. `node prepare-flux.cjs` ждёт окончания скачивания, конвертирует шардированные FLUX и T5 в Q4_K, затем запускает проверку FLUX 512×512 / 28 шагов / seed 42 при свободном GPU. Работа обоих процессов продолжается при закрытии браузера. На время скачивания профиль FLUX отображается недоступным; подготовленные веса обнаруживаются без перезапуска сервера. Ошибки и прогресс показаны в интерфейсе; журналы находятся в `logs/flux-*`, итог GPU-теста — в `FLUX_TEST_RESULTS.json`. Завершение реальной проверки подтверждает статус «Готова», а не само наличие профиля.

FLUX использует CLIP-L, квантованный T5 и свой VAE, CFG 1 и отдельный Guidance (по умолчанию 3.5). Негативный промпт при CFG 1 не используется. Все вычисления генерации настроены на CUDA0; неактивные веса могут храниться в RAM. Исходники остаются на диске после квантования.

Системную инструкцию генератора промптов можно редактировать в открытой панели. По умолчанию модель пишет фотореалистичный промпт, кроме запросов с явно указанным другим стилем: аниме, акварель, иллюстрация и т.д. Температура, top-p, top-k, min-p, штраф повторов, лимит ответа, контекст, seed текста, бюджет рассуждений и примеры настраиваются отдельно и сохраняются в браузере. Число шагов изображения: от 1 до 1000; большое число шагов не гарантирует пропорционального улучшения качества.

Постоянный порт Studio — **8795**. Для применения изменений запусти `Restart Studio.cmd` от администратора: он проверяет старые экземпляры, отказывается прерывать активную генерацию, закрывает только идентифицированные Studio, перезапускает подготовку FLUX и добавляет правило Windows Firewall для входящих подключений от локальной подсети. Скачивание FLUX не останавливается. После этого адрес ПК — http://127.0.0.1:8795, адрес телефона в текущей сети — http://192.168.0.138:8795. Телефон должен быть подключён к той же сети; роутер с изоляцией клиентов может блокировать доступ. Актуальный сетевой адрес показан в интерфейсе. Доступ из Интернета и проброс портов не настраиваются.

## GPU и последовательность

Модель промптов запускается через llama.cpp с CUDA0, всеми слоями на GPU и контекстом 2048. После завершения запроса процесс полностью закрывается, включая освобождение VRAM. Qwen запускается только после завершения этого процесса. Внутри Qwen текстовый энкодер, diffusion и VAE используют `--backend cuda0`. `--offload-to-cpu` хранит неактивные веса в системной RAM и переносит их на GPU по мере надобности; это **не CPU-режим генерации**. Ни `--clip-on-cpu`, ни `--vae-on-cpu` не используются.

По умолчанию для изображения выбран `qwen-image-2.1-UC-Q4_K_M.gguf`; другой скачанный совместимый checkpoint можно выбрать в интерфейсе. В приложении нет проверки содержания промптов, модератора или safety checker. Стандартный Qwen3-VL используется внутри Qwen как текстовый энкодер: приложение не обращается к нему за диалоговым ответом. Автор модели Gemma заявляет Deep Abliterated; описание метода: https://huggingface.co/Madras1/Gemma-4-E4B-Abliterated-Uncensored . Маркировка и опубликованные проверки автора не являются гарантией поведения на каждом возможном промпте.

На RTX 4060 8 ГБ нужно выгрузить модели других приложений. Studio проверяет наличие примерно 6.2 ГБ свободной VRAM и сообщает об ошибке вместо переключения на CPU. Одновременно выполняется только одна задача. Кнопка «Остановить» закрывает процесс текущей модели. Во время работы не запускай другой LLM на этой же видеокарте.

Начальные параметры: 512×512, 20 шагов, Euler, CFG 6. Размеры кратны 32. Для технического теста: 256×256, 4 шага; качество на таком пресете ограничено. Seed −1 выбирает случайное число; фактический seed сохраняется с изображением. Веса занимают примерно 10.3 ГБ, CUDA runtime — ещё около 0.9 ГБ архивов плюс распакованные файлы.

## Результаты и диагностика

`outputs/` содержит PNG и JSON с промптом, seed и параметрами. `logs/` содержит отдельные журналы Llama/Qwen для каждого запроса. `data/` хранит статусы задач. Интерфейс доступен только на локальном компьютере. Запросы не отправляются во внешние AI API.

`node --test core.test.cjs` — проверки параметров, моделей до 13B, GPU-аргументов, последовательности и отмены. `node verify.cjs` — реальные GPU-тесты: три промпта, затем три генерации; ожидает окончания установки. Протокол сохраняется в `TEST_RESULTS.json`. Команда требует запущенного Studio, не запускай её одновременно с ручными задачами.

## Проверено на этом компьютере

Выбор моделей: 8 автоматических проверок прошли; сохранение выбора Llama после перезагрузки страницы проверено в браузере. Реальный запуск выбранной Llama-3.1-8B-Lexi → Qwen UC (256×256, 4 шага, seed 42) завершился за 17.0 с, PNG сохранён, обе модели записаны в метаданных. Протокол: `MODEL_SELECTION_TEST_RESULTS.json`; вид панели: `Model Selection Preview.png`.

3 октября 2026 года: RTX 4060 8 ГБ, 64 ГБ RAM. Все файлы установки проверены по SHA256. Шесть проверок кода прошли. Три теста промптов прошли: английский текст из русской идеи, сохранение надписи LUNA и акварельного стиля, предметное фото. Llama загрузила 33/33 слоя на GPU и освобождала VRAM после каждого запроса.

Реальные генерации: 256×256 / 4 шага — 13.1 с; 512×512 / 20 шагов — 37.3 с; полный сценарий Llama → Qwen 512×512 / 20 шагов — 41.0 с. После каждой генерации оставалось около 7 ГБ свободной VRAM. Короткий тест 256×256 проверяет работу движка и сохранение PNG, его качество недостаточно для обычной генерации. Изображения 512×512 осмотрены визуально. Подробные результаты: `TEST_RESULTS.json`; пример интерфейса: `Studio Preview.png`.
