# Image Studio

**От идеи к промпту. От промпта к изображению.**

## Возможности

| | Что доступно |
|---|---|
| **Три способа работы** | Написать промпт, создать изображение напрямую или выполнить оба этапа. |
| **Выбор моделей** | Независимые списки текстовых моделей и генераторов изображений. |
| **Настройка результата** | Размер, seed, шаги, sampler и параметры текстовой генерации. |
| **Последовательная работа** | Текстовая модель освобождает VRAM перед генерацией изображения. |
| **Сохранение результата** | PNG и JSON с промптом, seed, моделями и настройками. |
| **Отмена задачи** | Остановка текущего процесса модели. |

Текстовые GGUF обслуживает **llama.cpp**, изображения — **stable-diffusion.cpp**. В конфигурации предусмотрены Qwen-Image 2.1 и отдельный профиль FLUX. Доступность профиля зависит от подготовки весов и компонентов.

## Запуск

Потребуются Windows, Node.js **22+**, NVIDIA GPU с CUDA и свободная видеопамять. Текущая конфигурация проверяет наличие примерно **6,2 ГБ** перед запуском.

```powershell
git clone https://github.com/safromaks-cell/image-studio.git
cd image-studio
```

1. Запусти **`Install.cmd`**: он скачивает компоненты изображений и CUDA runtime, проверяет SHA-256 и поддерживает продолжение загрузки.
2. Для написания промптов подготовь текстовый GGUF и `llama-server.exe`.
3. Проверь локальные пути в `config.json`.
4. Запусти **`Start Studio.cmd`** или выполни `npm start`.

Открой **[localhost:8795](http://127.0.0.1:8795)**. Модели загружаются при выполнении задачи.

### Пути в конфигурации

| Параметр | Что указать |
|---|---|
| `llamaExe` | Путь к совместимому `llama-server.exe` |
| `modelRoot` | Каталог текстовых GGUF |
| `promptModel` | Путь к текстовой модели по умолчанию |

Исходный `config.json` содержит абсолютные пути прежней установки. На другом компьютере замени их своими. Текстовый движок и модель можно взять из настроенной установки [Simple Chat](https://github.com/safromaks-cell/simple-chat).

## От идеи до результата

| Кнопка | Результат |
|---|---|
| **Написать промпт** | Текстовая модель превращает идею в промпт. |
| **Создать изображение** | Генератор использует введённый текст напрямую. |
| **Улучшить и создать** | Сначала готовится промпт, затем создаётся изображение. |

Выбор моделей сохраняется в браузере. Незавершённые загрузки и вспомогательные энкодеры не предлагаются в качестве генераторов.

## Настройки

| Параметр | Для чего нужен |
|---|---|
| **Размер** | Ширина и высота изображения, кратные 32 |
| **Шаги** | Число итераций генерации |
| **Seed** | Настройки случайности; `−1` выбирает новый seed |
| **Sampler и CFG** | Способ генерации и сила следования промпту |
| **Настройки текста** | Системная инструкция, температура, top-p, контекст и другие параметры |

Начальный пресет Qwen-Image: **512 × 512 · 20 шагов · Euler · CFG 6**. Для короткой технической проверки: **256 × 256 · 4 шага**. Большее число шагов само по себе не гарантирует более качественную картинку.

У FLUX собственные энкодеры, VAE и параметры Guidance. Загрузка и подготовка запускаются отдельно:

```powershell
node download-flux.cjs
node prepare-flux.cjs
```

## Работа на GPU

Задачи выполняются по очереди. После подготовки промпта текстовая модель закрывается и освобождает VRAM, затем запускается генератор изображения. Вычисления настроены на CUDA; неактивные веса генератора могут переноситься между RAM и GPU.

Для текстового этапа текущий режим допускает модели до 13B. При нехватке видеопамяти приложение сообщает об ошибке. Перед генерацией освободи GPU от моделей других приложений.

## Результаты и доступ

| Каталог | Содержимое |
|---|---|
| `outputs/` | Изображения PNG и JSON с параметрами |
| `logs/` | Журналы движков и задач |
| `data/` | Статусы и локальные данные |
| `models/` | Веса генераторов, энкодеров и VAE |
| `runtime/` | Движки и CUDA-библиотеки |

Эти каталоги исключены из репозитория. Запросы генерации не отправляются во внешние AI API.

Порт студии — **8795**. Доступ с другого устройства определяется `listenHost` в `config.json` и правилами Windows Firewall. Скрипты доступа рассчитаны на локальную подсеть.

## Проверки

```powershell
npm test
```

Команда проверяет параметры и логику без генерации изображений. Для реального GPU-прогона есть `npm run verify`: он требует подготовленных моделей и запущенной студии.
